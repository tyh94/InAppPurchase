# Тесты для InAppPurchase

Этот каталог содержит комплексные тесты для модуля InAppPurchase, написанные с использованием нового фреймворка `Testing` от Apple.

## Структура тестов

### Основные файлы тестов:

1. **Mocks.swift** - Моки для тестирования
   - `MockPurchaseManager` - мок для PurchaseManager
   - `MockKeyValueStorage` - мок для KeyValueStorage
   - `MockLogger` - мок для Logger
   - `MockProduct` - структура для тестирования продуктов

2. **PremiumServiceTests.swift** - Основные тесты PremiumService
   - Тестирование инициализации и конфигурации
   - Тестирование основных операций (start, purchase, restore)
   - Тестирование @Published свойств
   - Тестирование обработки ошибок
   - Тестирование логирования

3. **PremiumServiceIntegrationTests.swift** - Интеграционные тесты
   - Полный цикл покупки
   - Тестирование подписок с истечением
   - Тестирование восстановления покупок
   - Тестирование персистентности данных
   - Тестирование кастомных ключей хранения

4. **PremiumServiceEdgeCasesTests.swift** - Тесты граничных случаев
   - Тестирование экстремальных значений дат
   - Тестирование пустых и очень больших коллекций
   - Тестирование специальных символов в ключах
   - Тестирование множественных вызовов
   - Тестирование множественных экземпляров

5. **PremiumServicePerformanceTests.swift** - Тесты производительности
   - Тестирование множественных операций с хранилищем
   - Тестирование создания множественных сервисов
   - Тестирование сериализации PremiumStatus
   - Тестирование логирования
   - Тестирование проверки премиум статуса

6. **InAppPurchaseTests.swift** - Базовые и smoke тесты
   - Базовые тесты для всех компонентов
   - Smoke тесты для полного цикла работы

## Запуск тестов

### Через Swift Package Manager:

```bash
# Запуск всех тестов
swift test

# Запуск тестов с подробным выводом
swift test --verbose

# Запуск конкретного теста
swift test --filter "PremiumServiceTests"

# Запуск тестов производительности
swift test --filter "PerformanceTests"
```

### Через Xcode:

1. Откройте Package.swift в Xcode
2. Выберите схему "InAppPurchase-Package"
3. Нажмите Cmd+U для запуска тестов
4. Или выберите Product → Test

## Особенности тестирования

### Использование Testing Framework

Тесты используют новый фреймворк `Testing` от Apple, который предоставляет:

- `@Test` атрибут для пометки тестовых функций
- `#expect()` макрос для проверок
- Поддержку async/await тестов
- Встроенную поддержку в Swift 6.0+

### Моки и заглушки

Для изоляции тестов используются моки:

- `MockPurchaseManager` - имитирует поведение PurchaseManager
- `MockKeyValueStorage` - имитирует поведение хранилища
- `MockLogger` - имитирует поведение логгера
- `MockProduct` - структура для тестирования продуктов
- Все моки поддерживают настройку ошибок для тестирования edge cases

### Тестирование async кода

Многие тесты используют `async/await` для тестирования асинхронных операций:

```swift
@Test("Тест асинхронной операции")
func testAsyncOperation() async throws {
    let service = PremiumService(...)
    await service.start()
    #expect(service.isPremium == true)
}
```

### Тестирование @Published свойств

Тесты проверяют корректность обновления @Published свойств в PremiumService:

```swift
@Test("Тест @Published свойств")
func testPublishedProperties() async throws {
    let service = PremiumService(...)
    // Изменяем состояние
    await service.start()
    // Проверяем, что свойства обновились
    #expect(service.isPremium == true)
}
```

## Добавление новых тестов

При добавлении новых тестов следуйте конвенциям:

1. Используйте `@Test` атрибут с описательным названием
2. Группируйте связанные тесты в отдельные классы
3. Используйте моки для изоляции тестов
4. Добавляйте тесты для граничных случаев
5. Используйте `#expect()` для проверок

## Пример добавления нового теста:

```swift
@Test("Новый тест для новой функциональности")
func testNewFeature() throws {
    let service = PremiumService(...)
    // Тестовая логика
    #expect(service.someProperty == expectedValue)
}
```

## Примечания по StoreKit

В тестах используются моки вместо реальных StoreKit объектов, так как:

- `Product` не имеет публичных инициализаторов
- `Transaction` требует специальной конфигурации
- В реальных тестах рекомендуется использовать StoreKit Test Configuration

Для интеграционного тестирования с реальными покупками используйте:
- StoreKit Test Configuration
- Sandbox окружение
- Тестовые аккаунты App Store Connect
